Context compaction

Compaction replaces the old part of a conversation’s history with a summary, so that a long agent session fits in the context window. It is cheap when the same model writes the summary on the same prompt prefix before the cache expires: the history is then read from the cache, and you pay mostly for generating the summary.

When the harness compacts

  • At a threshold. When the context nears the limit, the harness summarises the history before the next turn and leaves room in the window for the instruction and the summary itself. Claude Code does this by default at the window limit, and Codex at 90% of the window (as of October 2026). The Claude API (in beta) and OpenAI can compact on the server, at a threshold you set or on request.
  • By hand, once a task is done: you choose the moment instead of waiting for auto-compaction to arrive mid-work. /compact in Claude Code takes an instruction on what to keep. If you are abandoning a dead end, /rewind to an earlier turn is cheaper than compaction, because it returns to a prefix that is already in the cache.
  • Before the cache expires. Claude Code has idle compaction, announced in version 2.1.299 (14 October 2026): a conversation of 200k tokens or more with no request for about 54 minutes is summarised just before the one-hour cache ends. The next message then carries the summary instead of the whole history. It works in the terminal and only with the one-hour cache, which Claude Code turns on by default on a subscription. On a 200k window auto-compaction arrives earlier, so in practice it applies to models with a larger window.

How to compact without paying for the whole history

  • The summarisation call is a separate request on the same prefix as the conversation: the same model, the same tools and system prompt, the same history, with the summarisation instruction appended at the end. To the cache it looks almost like the previous turn’s request, so the history is read from the cache. A request with a different prompt and no tools differs from the very first token and pays full price for the whole conversation. A cheaper model also starts from an empty cache, because each model has its own, and it cannot read the main model’s encrypted thinking either.
  • Codex builds its compaction call the same way (code as of October 2026), but OpenAI does not document whether compaction reads the history from the cache, and advises comparing total input cost before and after it.
  • After compaction the system prompt with the tools still hits the cache, in the Claude API provided a cache_control marker (breakpoint) sits at its end (see “Prompt caching”). Claude Code reloads CLAUDE.md from disk, and it hits the cache only if it hasn’t changed. The summary is written anew.
  • Compact before the cache expires. After a longer absence the summarisation call pays full price for the whole history, which is why /compact after resuming an old session costs the most. It usually still pays off, because every later turn reads a short context instead of the whole history.
  • Replace the old part of the history with one summary instead of cutting individual messages out of it. After every cut, everything that follows it has to be written to the cache again: after compaction that is a short summary, after removing results right after the start it is almost the whole history. So clear old tool results rarely and in large batches, or leave it to the API (see “Context engineering and memory”).

What survives compaction

  • Claude Code first clears old tool results and only then summarises. It keeps the summary and the latest messages, and reloads the project’s main CLAUDE.md, the plan and up to five files that were read or edited, most recently changed first. Details from early in the conversation can be lost, so keep rules that always apply in CLAUDE.md.
  • In the Claude API the summary comes back as readable text that you send back unchanged in later requests. Compaction in OpenAI’s Responses API returns the user messages and one encrypted item, which according to OpenAI preserves the model’s understanding of the conversation. In both cases only evals on long sessions show what the summary lost.
  • A model’s thinking comes back from the API encrypted, so only the provider can summarise it: on-demand compaction in the Claude API reads it, also with your own summarisation prompt. If you summarise yourself and send Claude models their thinking back, replace the whole history with one message or keep the latest turns without their thinking blocks. Models are trained for this: OpenAI trains Codex models to work across several context windows linked by compaction (GPT-5.1-Codex-Max, November 2025), and Anthropic writes that it trains Claude models on long tasks with a summary of the whole session in a single message.
