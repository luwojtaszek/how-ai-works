Kompakcja kontekstu

Kompakcja zastępuje starą część historii rozmowy streszczeniem, żeby długa sesja agenta zmieściła się w oknie kontekstu. Jest tania, gdy streszczenie pisze ten sam model na tym samym początku promptu, zanim wygaśnie cache: historię czyta wtedy z cache’u, a płacisz głównie za wygenerowanie streszczenia.

Kiedy harness kompaktuje

  • Przy progu. Gdy kontekst zbliża się do limitu, harness streszcza historię przed następną turą i zostawia w oknie zapas na polecenie i samo streszczenie. Claude Code kompaktuje blisko limitu okna, a dokładny próg zależy od modelu i konfiguracji; Codex domyślnie przy 90% okna (stan na październik 2026). API Claude (w becie) i OpenAI potrafią kompaktować po stronie serwera, przy progu, który ustawiasz sam, albo na żądanie.
  • Ręcznie, po skończonym zadaniu: sam wybierasz moment, zamiast czekać, aż auto-kompakcja przyjdzie w środku pracy. /compact w Claude Code przyjmuje instrukcję, co zachować. Jeśli porzucasz ślepą uliczkę, /rewind do wcześniejszej tury jest tańszy od kompakcji, bo wraca do prefiksu, który już jest w cache’u.
  • Przed wygaśnięciem cache’u. Claude Code ma idle compaction, ogłoszoną w wersji 2.1.299 (14 października 2026): rozmowę od 200 tys. tokenów (domyślny próg), w której od ok. 54 minut nie było requestu, streszcza tuż przed końcem godzinnego cache’u, o ile terminal z sesją jest otwarty, a komputer nie śpi. Następna wiadomość niesie wtedy streszczenie zamiast całej historii. Działa w terminalu i tylko przy godzinnym cache’u, który Claude Code domyślnie włącza w subskrypcji. Przy oknie 200 tys. auto-kompakcja przychodzi wcześniej, więc w praktyce dotyczy modeli z większym oknem.

Jak kompaktować bez płacenia za całą historię

  • Wywołanie streszczające to osobny request na tym samym prefiksie co rozmowa: ten sam model, te same narzędzia i system prompt, ta sama historia, a polecenie streszczenia dopisane na końcu. Dla cache’u to prawie ten sam request co poprzednia tura, więc historia jest czytana z cache’u. Request z innym promptem i bez narzędzi różni się już od pierwszego tokena i płaci pełną cenę za całą rozmowę. Tańszy model zaczyna od pustego cache’u, bo każdy model ma własny, a to, czy przeczyta wcześniejsze myślenie, zależy od pary modeli.
  • Codex buduje wywołanie kompakcji tak samo (kod z października 2026). OpenAI pozwala sterować cache’em także przy kompakcji i raportuje w niej tokeny z cache’u, ale trafień nie gwarantuje: radzi je zmierzyć i porównać łączny koszt wejścia przed kompakcją i po niej.
  • Po kompakcji system prompt z narzędziami dalej trafia w cache, w API Claude pod warunkiem, że znacznik cache_control (breakpoint) stoi na jego końcu (temat „Prompt caching”). Claude Code wczytuje CLAUDE.md od nowa z dysku, a ten trafia w cache tylko wtedy, gdy się nie zmienił. Od nowa zapisuje się streszczenie.
  • Kompaktuj, zanim cache wygaśnie. Po dłuższej nieobecności wywołanie streszczające płaci pełną cenę za całą historię, dlatego /compact po wznowieniu starej sesji kosztuje najwięcej. Zwykle i tak się opłaca, bo każda kolejna tura czyta krótki kontekst zamiast całej historii.
  • Zastępuj starą część historii jednym streszczeniem, zamiast wycinać z niej pojedyncze wiadomości. Po każdym cięciu wszystko, co stoi za nim, trzeba zapisać w cache’u od nowa: po kompakcji to krótkie streszczenie, a po wycięciu wyników tuż za początkiem prawie cała historia. Stare wyniki narzędzi czyść więc rzadko i dużymi porcjami albo zostaw to API (temat „Context engineering i pamięć”).

Co zostaje po kompakcji

  • Claude Code najpierw czyści stare wyniki narzędzi, a dopiero potem streszcza. Zostawia streszczenie i ostatnie wiadomości, a od nowa wczytuje główny CLAUDE.md projektu, plan i do pięciu czytanych albo edytowanych plików, najpierw najświeżej zmienionych. Szczegóły z początku rozmowy mogą przepaść, więc zasady obowiązujące zawsze trzymaj w CLAUDE.md.
  • W API Claude streszczenie wraca jako czytelny tekst, który odsyłasz w kolejnych requestach bez zmian. Responses API OpenAI zwraca skrócone okno kontekstu z zaszyfrowanym elementem kompakcji, który według OpenAI zachowuje to, jak model rozumiał rozmowę, i ewentualnie z zachowanymi elementami historii. Całe zwrócone okno odsyłasz bez zmian. Co streszczenie zgubiło, pokaże w obu przypadkach tylko ewaluacja na długich sesjach.
  • Myślenie modelu wraca z API zaszyfrowane, więc streścić je może tylko dostawca: kompakcja na żądanie w API Claude czyta je, także z własnym promptem streszczającym. Jeśli streszczasz sam i odsyłasz modelom Claude ich myślenie, zastąp całą historię jedną wiadomością albo zostaw ostatnie tury bez ich bloków myślenia. Modele są do tego trenowane: OpenAI uczy modele Codex pracy w wielu oknach kontekstu połączonych kompakcją (GPT-5.1-Codex-Max, listopad 2025), a Anthropic pisze, że trenuje modele Claude na długich zadaniach ze streszczeniem całej sesji w jednej wiadomości.
